RAG 能解决什么问题?

Retrival Augmented Generation (检索增强生成)

- 知识滞后
- 知识缺失
- 幻觉
  - 训练时过度泛化(懂得太多了)
  - 没有真正学习到训练数据中深层含义
  - 缺乏特定领域相关知识

大模型生成内容不可控, 尤其是在金融和医疗领域. 我们需要不确定系统和确定系统的融合.

为了改善大模型在

- 实效性
- 可靠性
- 准确性

方面的不足

检索向量数据库, 检索出相关数据片段,
融合提示词, 作为提示词中的参考资料, 强化提示词.

提供外部的数据.

稠密向量, 稀疏向量(可能有百万维)

嵌入模型找到相似
重排序模型找到精排结果

- 优点
  - 更丰富的上下文和数据样本. 不需要用户提供过多的背景描述
  - RAG 可以提升问答内容的实效性和可靠性
  - 保护业务数据隐私性
- 缺点
  - 响应时延更长(涉及外部系统数据检索)
  - 消耗更多的 Token

## 稠密向量和稀疏向量

稠密向量:
指定维度, 申明 1024 维度, 那么向量一定是一个 1024 list 的 float

稀疏向量:
是个字典, k 是索引, v 是权重
